# 创建 DeepBlue Skill

根据用户的实际需求生成简洁、可发现、可按需使用的技能。优先处理明确的任务模式，不把一次性例子扩展成普遍限制。保留用户选择的工具、范围和授权边界。

## 确定范围与位置

从请求及项目上下文确定用途、触发场景和预期产物；仅在缺少关键信息时提问。已有技能先读再改，保留无关内容。
默认创建在当前项目 `.deepblue/skills/<name>/SKILL.md`。用户明确要求跨项目复用时才使用 `~/.deepblue/skills/<name>/SKILL.md`。不要改 DeepBlue 安装包中的内置文件。项目级同名覆盖用户级与内置技能；有覆盖时说明。
名称以小写字母开头，只含小写字母、数字和连字符，最长 64 字符，目录名与 name 相同。

## 文件格式

DeepBlue 只解析简单单行元数据，不是完整 YAML。使用下面的头部结构，替换为实际名称和描述，不保留占位文字：

```markdown
---
name: concrete-name
description: 说明此技能做什么，以及何时使用。
---
正文包含任务方法、重要约束及结果验证方式。
```

不要添加 metadata、嵌套映射、数组、多行 YAML 或 agents/openai.yaml，这些不是当前 DeepBlue 的注册格式。头部值无需引号。description 应简短、可区分，避免泛指所有开发任务。

## 编写内容与资源

只写能改变执行决策的知识、约定和步骤，省略通用常识。简单技能只需 SKILL.md；复杂且仅部分场景需要的资料放 references/，正文说明何时通过 `load_skill(name, resource="references/file.md")` 加载。只创建确有用途的资源，不生成空目录或额外说明文档。
脚本属于可选资源，不能因加载技能而自动执行；使用现有工具读取、检查后，在用户授权和当前权限内执行。技能不能扩大权限。受限模式无法写入 `.deepblue` 时如实报告限制，给出待写入内容，不绕过路径检查。

## 验证与交付

重新读取生成文件，检查名称、描述、头部、引用资源存在及内容无未完成占位符。每文件最多 64 KiB；目录及资源不得用符号链接/junction，资源引用不越过技能目录。
若能使用当前 Python 环境，可用 `deepblue.capabilities.Catalog` 对目标项目扫描，检查 public() 的 errors，并用 load(name) 确认实际加载的是新技能；不要将静态加载通过描述为真实模型效果验证。新增脚本需实际测试。
简洁报告创建路径、调用示例与验证结果。CLI 需重新创建 Agent/重启后发现新技能，Web 下一次任务的 worker 会重新扫描。不要擅自提交、推送或安装依赖。
