# DeepBlue Web 下一阶段实现计划

审查日期：2026-09-21。基线：本地 DeepBlue v0.5.0 与同级目录 pi-web 源码。跟踪：[Issue #8](https://github.com/plussea/deepblue/issues/8)，已有最小工作台交付见 [Issue #7](https://github.com/plussea/deepblue/issues/7)。

目前已经有三栏工作台和完整 Agent 接入，但与 pi-web 的主要差距在会话使用、运行状态可靠性和编码审阅流程。建议先把现有 Web 做到可连续使用，再扩展项目与任务编排；不需要为了对齐功能而重写成 Next.js。

更新：v0.6/v0.7 已按此计划完成本地实现与验收，见 [v0.6](v0.6.md)、[v0.7](v0.7.md) 及 Issue #9–#13；v0.8 仍为候选范围。以下差距矩阵保留规划时的 v0.5 基线，不能当作当前版本功能清单。

2026-09-21 补充：v0.7.2 已完成本地真实 Web 四组验收、15 组浏览器回归和 108 项 Python 回归，并改为浅色简约界面、修复错误提示刷新丢失；见 [验收记录](v0.7.2.md) 与 Issue #15/#16。源码随 v0.7.2 提交交付，远程同步状态见对应 Issue。下一步仍是小规模真实任务评测，再评估 v0.8 多项目、分叉与队列。

本文最初为实现计划。结论来自源码与文档检查，未运行 pi-web 全套测试，也没有进行真实模型效果对比。既有 91 项测试的通过记录属于 v0.5，不代表本计划已经验收。

## 2. 应先处理的现有行为

以下为静态代码检查发现，其中竞态是待通过测试复现的风险，不声称已在浏览器重现。

1. `poll()` 每次调用 `scrollChat()`，阅读旧消息时也会被拉回底部。改为仅在用户接近底部时跟随，其他情况显示“有新消息”。
2. 发送请求返回后才进入 busy 状态，连续点击存在重复请求窗口。前端立即锁定，后端按请求 ID 去重，不能仅依赖“当前忙”。
3. 轮询捕获异常后持续重试，缺少网络断开、认证失败、任务不存在的区分。增加有上限退避、显式恢复操作和终止条件。
4. 会话读取没有请求代次校验，快速切换可能由较晚返回的旧响应覆盖新会话。使用请求取消及选择版本校验。
5. 新建会话通过刷新页面实现，草稿和填写的验收命令丢失。改用显式 UI 状态转换。
6. 取消请求操作当前全局任务，缺少客户端指定任务身份的保护。多标签页下必须按 job_id 校验，避免取消另一任务。
7. 历史接口虽然只返回末尾消息，后端仍加载完整会话；直接增加“加载更多”不能解决长历史读取成本。需要元数据索引、分页读取与运行快照。
8. 运行结束后显示“就绪”，用户需要查看侧栏才知道验证结果。保留最终执行、验收和恢复状态，并提供详情入口。

## 3. v0.6：稳定性、会话管理与 DeepSeek 配置

目标：在单项目、全局单任务的约束下，可以连续使用、刷新与重新连接，不混淆会话和任务。

### A. 任务状态与连接（先实施）

- 引入明确的 job_id、session_id、request_id；运行、取消、读取事件全部绑定身份。提交响应丢失后查询原任务，不自动重发用户任务。
- 定义 queued/running/cancelling/completed/failed/interrupted 等生命周期；执行状态与 verification_status 分开展示。
- 抽取任务管理模块，持久化最小任务元数据，提供状态快照与带序号事件。游标过期返回明确的重新同步信号；快照标明最后序号，避免漏事件或重复展示。
- 首先修正轮询协议；随后同模块引入 Web SSE、心跳和重连，轮询保留为兼容回退。SSE 本身不是可靠性保证。
- 服务重启时将未确认任务核对为 interrupted/unknown，读取现有恢复报告；不重放工具、不按旧 PID 接管进程，也不把重启当成成功。
- 修复上节滚动、重复发送、异步会话响应及终止重试问题。

验收：连续点击只生成一个任务；断网再连接消息不重复；事件超过缓存后能重新同步；两个标签页不能误取消彼此任务；后端重启明确显示中断且没有重放副作用；停止过程中保留真实的最终执行结果。

### B. 会话体验（依赖 A 的运行快照）

- 会话列表分页、重命名、归档/恢复、Markdown/JSON 导出；先不加入永久删除。
- 分页加载历史，支持内容搜索与取消过期搜索；元数据索引可由 JSONL 重建，原始日志仍为事实来源。
- 草稿按项目/会话隔离，保存输入与验收命令；浏览器刷新恢复选择，发送失败保留草稿。草稿不保存 API Key，并提供清除入口。
- 任务运行时允许浏览其他会话，始终标明后台运行任务；全局仍只允许执行一个任务。运行中会话通过快照读取，避免与日志写锁冲突。

验收：超过 100 个会话和 200 条消息仍可访问早期内容；归档后可恢复；切换和刷新不串草稿；导出保留原始文本；运行期间浏览会话不影响 worker。增加至少千条消息夹具，记录首屏加载与增量读取成本。

### C. DeepSeek 设置与连接检查

- 增加设置面板：模型、接口地址、超时和配置来源，保留现有别名及环境变量优先级。环境提供的值显示为受环境管理。
- 未由环境配置的 Key 可在本次服务进程内设置和清除；不回传 Key，不存入 localStorage、会话、日志或配置导出。重启后需重新输入；持久凭据存储另立事项。
- 配置在创建任务时冻结，后续修改不改变在途任务；Key 不放入子进程命令行，延续工具子进程环境清理。
- “测试连接”由用户显式点击，标明会发起模型请求；分别展示配置错误、认证、余额、限流、超时和连接成功，不自动反复测试。

验收：缺 Key 可通过界面完成配置；响应和日志不含密钥；运行中修改设置不影响旧任务；现有 CLI 配置行为不变。默认用模拟 HTTP 服务，真实付费联调单独记录。

## 4. v0.7：完整的编码审阅流程

依赖 v0.6 的会话与任务身份，不新增并行执行。

### A. 消息、工具与文件

- 支持常用 Markdown（标题、列表、表格、链接）、代码复制与语法高亮，禁用原始 HTML，校验链接协议；不把模型输出直接交给 innerHTML。
- 工具卡片显示工具名、目标文件/命令、运行状态、耗时、退出码；大结果按需加载，保留原文入口。
- 文本文件预览增加行号、行定位、搜索和刷新；消息中的项目文件链接可打开预览。
- 增加 @文件引用，发送前解析为明确的相对路径；读取仍走 Agent 工具，不默默把整个文件塞入提示词。路径访问延续服务端边界校验。
- 渲染依赖采用固定版本、本地资源及许可证记录，不依赖公共 CDN；Python 后端保持不变。

验收：代码可原样复制；恶意 HTML/链接不执行；中文与特殊字符路径可定位；大型工具输出不阻塞对话；窄屏能完成输入、预览和返回流程。

### B. 修改审阅、验证证据与恢复详情

- 提供只读 Git 状态与 diff，区分暂存、未暂存、未跟踪文件；非 Git 项目退回 Agent 已记录的修改信息。
- 任务开始记录已有修改，界面区分“当前工作区差异”与“本次任务观察到的变化”；不能把全部 git diff 归因于 Agent。
- 验证卡片展示命令、cwd、退出码、耗时、日志、文件指纹和 stale 原因；保持“未验证”和“指定检查通过”的语义差异。
- 通过服务器登记的 evidence_id 读取证据日志，避免暴露任意本地路径读取接口；支持大小上限与分页。
- 恢复卡片展开未知操作、外部文件变化和重新读取建议；不自动回滚文件或重跑未知 Shell。

验收：既有用户修改不会被标作 Agent 独占修改；Git 暂存/未暂存均可查看；非 Git 项目正常工作；验证后修改文件显示 stale；日志在工作目录外仍能通过合法证据 ID 读取，伪造 ID 不得越界。

## 5. v0.8：多项目与任务编排

此阶段为候选范围，在 v0.7 实际使用后再锁定，不作为 v0.6 的前置条件。

1. 项目选择、最近项目、分组与配置隔离。由服务端验证目录，切换项目不改变正在运行任务的 cwd，初期继续全局单任务。
2. 从历史轮次分叉为独立会话，记录 parent_session/branch_point，保持工具消息配对。会话分叉不等于代码快照回滚，UI 必须明确当前文件状态。
3. 后续消息队列：可查看、修改、删除；上一任务结束后按序执行。运行中 steering 要另行定义安全的轮次边界，不能直接插入正在执行的工具调用。
4. Git worktree 独立评估目录生命周期、脏工作区和清理行为后实施；先提供选择现有 worktree，不自动删除目录。

验收：跨项目不串文件/草稿/配置；分支保留来源且不改原会话；队列取消不会执行；重启不自动重放未确认的排队任务；工作树切换不覆盖用户修改。

## 6. 技术拆分与交付方式

- 后端：逐步从 `web.py` 分离任务生命周期、会话查询、配置和证据/文件服务；保留 Agent、Session、验证、恢复逻辑共用，避免 Web 另写一套运行时。
- 前端：把 `app.js` 拆成 API、状态、连接、会话、渲染与文件模块；先使用原生 ES modules，不以引入 React 为本阶段目标。
- 拟定 API：任务创建返回 job_id；任务状态/事件/取消按 ID 操作；会话列表与消息使用游标；配置 GET 只返回脱敏状态；证据按 ID 访问。实施时先确定协议与测试，再接 UI。
- 测试：核心 unittest 持续回归；新增浏览器自动化开发依赖，覆盖断网、刷新、重复提交、双标签页、长历史、草稿、渲染和窄屏。模拟模型为默认，真实 DeepSeek 验收单独运行并记录成本。
- 每模块完成时更新 README、版本文档、对应 Issue；记录本地实现/测试/提交/同步状态。打包后验证静态模块、资源和安装入口，防止开发目录可用但 wheel 缺文件。

建议执行顺序：**v0.6-A → v0.6-B → v0.6-C → v0.7-A → v0.7-B → 评估 v0.8**。A 是可靠性基础，不能被外观优化取代。暂不承诺工期，先用 A 的实际改造量评估后续工作。

Issue #8 为总跟踪；开始每个模块前搜索已有事项，再按上面的模块标题建立实施 Issue 并回链。#7 保留原最小版本范围，避免把已验收功能与未来功能混为一谈。

近期不纳入：多供应商、订阅登录、图片模型输入、完整办公文档预览、终端模拟器、插件市场、多 Agent、公网部署与账号系统。它们需要独立的产品和运行边界设计，不能仅通过增加按钮获得支持。
