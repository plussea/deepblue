## 第一阶段具体设计

- 将评测预算客户端移入核心，保持任务局部额度与批次总额度两级保护。每次 run/retry 创建独立运行额度，累计会话用量保留；retry 不是绕过同一次运行的计数。
- CLI/Web 启动参数提供最大请求数、Token 门槛、协作时间和检查预留时间；未配置 Token/时间限制时不擅自施加新的收费门槛。默认请求额度覆盖步骤与有界自动压缩。
- 自动压缩与修复使用同一个预算客户端；记录每次请求的估计和实际用量，失败请求也占请求额度。用量未知且启用 Token 门槛时阻止后续请求。
- 使用保守准入估计，不宣称精确分词或金额硬上限；网络在途请求和指纹扫描可能延迟停止。第一阶段不自动动态提额。
- 模型正常结束保持现有失败修复循环；步数、上下文、截断或预算停止后只做一次最终配置检查，不再发模型请求。用户取消、认证/网络失败不额外启动检查。
- 预留检查时间限制新的模型请求；没有余时跳过检查并持久记录原因。以确定性 notice 汇报执行状态、验收状态和预算，不依赖一次额外模型总结。
- 新检查与当前文件指纹绑定；不得把预算停止改写为 completed，也不得因未正常结束把刚通过的独立检查直接写成 stale。

## P0.3 实现记录（2026-09-23）

跟踪 [Issue #19](https://github.com/plussea/deepblue/issues/19)。默认启用有界运行内估计校准及最多 2 次修改后主动验收，提供 `--budget-estimator conservative` 与 `--active-checks 0` 对照开关，CLI/Web/评测一致。

校准仅使用同工具声明、相近请求规模、有效供应商 prompt_tokens 的至少 3 个样本；取比例上界加 25% 余量及 1/4 字节下界，预留完整输出与 512 Token，不增加总额度。缺失用量/失败请求重置样本，低估禁用该声明本次运行的校准。保留最近 100 次计量明细及累计值；不持久化供跨模型复用的校准状态。

主动验证比较工具批次前后工作区指纹，发现变化后执行配置检查并反馈给模型；主动检查有独立次数上限，失败修复要求共享既有 max_repairs。每个失败证据仅反馈一次，防止相同失败版本反复消耗检查和请求。最终收尾复用同版本稳定证据，文件再变就重新检查。Shell 无论是否改文件均使缓存失效；发生检查副作用、错误或取消不缓存。外部服务和时间相关检查不受源码指纹保证。

通过检查只提示汇报，不强制宣告整个任务完成；保留预算、取消和步骤停止状态。P0.3 无网络测试与本机 Web worker 验证完成后进入 P1.1，新的真实模型效益仍需独立实验验证。此处没有覆盖历史对照记录或追加付费重跑。
