# v0.5：可核对的中断恢复

对应 [Issue #6](https://github.com/plussea/deepblue/issues/6)。记录 v0.5.0 阶段实现；包含在当前源码中。

## 工具执行记录

每次工具执行创建唯一 `operation_id`，记录 `call_id`、名称、对应消息位置及开始事件，先追加并 fsync，再执行工具。返回后先保存完成事件和真实结果，再添加对话中的 tool 消息。

文件操作记录绝对路径、执行前后内容 SHA-256。`write` 还记录目标内容的预期哈希；中断后可以判断当前内容是否与预期一致。`edit` 未提前计算完整目标内容，缺少完成事件时只报告变化或未知，不推断修改成功。文件核对最多读取 8 MiB，超大文件、读取失败或期间变化返回 unknown。

Shell 启动时记录 PID、启动时间、执行目录、命令与日志路径。恢复不会根据旧 PID 查询身份、终止进程或重新执行命令。已结束、可能仍运行和副作用状态无法仅由 JSONL 确认。

## 恢复流程

1. 加载并锁定会话；仅修复未提交的最后半行，完整行损坏明确报错。
2. 已有完成事件、缺少 tool 消息：补回已知结果，不重复执行。
3. 没有完成事件：补回结果未知消息，保留未完成操作记录。
4. 只读比较当前文件、执行前状态、已知写入意图和最近完成操作后的状态，生成报告。
5. 报告展示已记录完成数量、未知操作和变化文件，并加入后续活动上下文作为事实参考。

`matches_intended_content` 只表示文件内容匹配意图，不是完整操作成功证明；`unchanged` 也不能证明命令从未执行，因为操作可能执行后恢复原状。未知记录保留，不提供自动“确认成功”或重放入口。

已有文件观察过期时，`write` / `edit` 会拒绝覆盖，要求先重新 `read`。失败的重读不更新为可信状态。该保护针对当前会话中已观察文件，不限制 Shell，不扫描未观察的整仓库，也不能取代文件锁或沙箱。

## 使用

```bash
deepblue --continue
```

恢复时有变化或未知操作会展示报告。交互中使用 `/recovery` 重新只读核对；Web 在右侧“状态”页展示同一报告。

## 故障注入验收

新增恢复相关测试覆盖以下 7 类场景，均通过：

| 场景 | 观察结果 |
| --- | --- |
| 执行开始记录失败 | 工具不执行，目标文件不创建 |
| 文件已写入、完成事件未保存 | 文件保持一次写入结果，报告匹配意图，对话结果仍未知 |
| 完成事件已保存、tool 消息未保存 | 恢复真实结果，无重执行 |
| Shell 执行中取消 | 清理受管进程，保留 PID 与日志，未完成记录仍为 unknown |
| 恢复前用户修改文件 | 报告变化，不自动回滚 |
| 旧读取之后外部修改、模型尝试写入 | 拒绝覆盖；重读后才可修改 |
| 子进程写文件后调用 `os._exit(83)` | OS 释放会话锁；新进程恢复确认内容匹配意图，未重复写入 |

另保留原会话测试中的尾部半行修复与完整记录损坏检查。这里是规定故障点的工程回归，不是随机故障条件下的总体恢复完成率；没有 exactly-once、任意命令幂等或工作区回滚保证。Linux/macOS 分支尚未做平台验收。
