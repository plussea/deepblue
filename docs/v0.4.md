# v0.4：结构化上下文与自动压缩

对应 [Issue #5](https://github.com/plussea/deepblue/issues/5)，随 v0.5.0 阶段一并实现，包含在当前源码中。

## 行为

默认摘要使用 JSON 状态：`goals`、`constraints`、`changes`、`open_questions`、`next_steps`。字段必须完整且为有界字符串数组；非法 JSON、工具调用、输出截断、过长摘要、无收益摘要都不能替换原活动上下文。

程序另外补充 `verified_facts`：从原始用户消息复制反引号内的精确标记，以及包含“不要、禁止、必须、不得、不能、只允许、记住、标记”的约束原句；附带实际工具观察路径、最近验证日志引用、源会话和消息范围。模型生成的状态不作为验收事实。复制规则只覆盖上述显式模式，不是完整的语义一致性证明；引用的历史验证状态也不代表当前文件仍通过。

原句超过 600 字符、超过 32 条约束或 64 个标记，会拒绝压缩而保留历史。路径最多列 40 项并明确截断，验证证据最多保留最近 4 项，完整记录通过源会话回查。整体带来源摘要超过 16,000 字节时不提交。

自动触发默认阈值为 `max_context_bytes × 0.8`，可配置为 0.2–0.95。一次任务最多尝试 2 次，至少相隔 4 个 Agent 模型轮次；每次最多调用 2 次摘要 API，即自动摘要单任务最多 4 次请求。它们不占 `max_steps`，另有上限，均记录服务返回的用量。手动压缩最多 20 次摘要请求。

保留最近完整用户轮次，工具调用与结果配对。当前单轮太大而无法缩减时停止，不把一轮中的工具结果拆开。失败/取消只可能留下用量记录，不破坏已有摘要；原始 JSONL 始终保留。

工具结果超过 8 KiB 时，原始结果同时归档至会话附件。活动视图保留错误、退出码、路径和首尾节选，缺少归档时回退到原始记录。文件变化会将旧读取替换为过期提示，避免继续消费旧代码。原始消息不改写、不删除。

## 使用

```bash
deepblue --compact-threshold 0.75 --keep-turns 2
deepblue --no-auto-compact
deepblue --summary-format text
python scripts/context_compare.py
```

`text` 保留旧摘要协议，便于对照；`structured` 是默认策略。字节阈值是本地保护，不是模型 Token 窗口的精确估算。

## 本地对照

`scripts/context_compare.py` 使用同一份历史和固定摘要响应，不调用真实 API。所有策略保留相同目标、约束和标记，没有刻意降低基线预算。

| 策略 | 活动字节 | 摘要请求 | 精确标记/约束 | 原始消息 |
| --- | ---: | ---: | --- | ---: |
| 完整历史 | 34,965 | 0 | 保留 | 11 |
| 旧文本摘要 | 6,221 | 1 | 保留 | 11 |
| 结构化摘要 | 约 6,773 | 1 | 保留 | 11 |

结构化版本包含来源路径，字节数随临时路径长度略有变化。它比纯文本摘要略大，换取可检查字段与程序补充的事实。该结果仅验证机制，不代表真实模型的任务完成率、约束保留率或费用收益。真实长任务对照仍待执行。

## 测试

专项测试覆盖结构化验证、原始约束/标记及失败证据保留、摘要失败原子性、自动压缩与超长单轮停止、输出归档及旧读取失效。原 v0.2 文本摘要测试仍保留，确认兼容路径。整体回归结果见 README 与 Issue。
