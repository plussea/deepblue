# DeepBlue v0.2：流式交互、上下文压缩与项目搜索

实现日期：2026-09-20。关联 [Issue #3](https://github.com/plussea/deepblue/issues/3)。

## 新增能力

| 能力 | 使用方式 | 行为 |
| --- | --- | --- |
| 流式回复 | 默认开启，`--no-stream` 关闭 | 收到文本片段就显示，响应完整后才执行工具 |
| 手动压缩 | `/compact`、`/compact 1` | 生成历史摘要，保留系统提示和最近用户轮次 |
| 批量压缩 | `deepblue -c --compact --keep-turns 1` | 压缩当前目录最近会话并退出 |
| 文件名搜索 | 模型调用 `find` | 按文件名/相对路径 glob 定位文件 |
| 文本搜索 | 模型调用 `grep` | UTF-8 字面文本搜索，返回路径、行号、片段 |
| 多行输入 | `/paste`，单独一行 `/send` 提交 | 将多行代码或需求作为一条用户消息提交 |
| 会话状态 | `/status` | 查看上下文大小、历史/活动消息数、压缩次数及累计用量 |

## 关键实现

- `llm.py`：SSE 解析、文本增量回调、按 index 组装工具参数；要求收到结束原因和 `[DONE]`。支持最终内容块携带用量或独立用量块两种格式。
- `agent.py`：展示文本增量且不重复打印；中断的流不会保存为完整助手消息，也不会执行其中的工具。`length` 等异常结束仍按错误结果回传。
- `compaction.py`：无工具摘要请求，按用户轮次保留消息组。长历史分段汇总，全部成功后才提交压缩视图；失败/取消不会替换活动上下文。
- `session.py`：原始消息保留，追加摘要及保留边界；恢复时重建上下文，累计普通调用与摘要调用的用量。
- `tools/search.py`：有返回条数、字节数、扫描条目数与时间预算的搜索；跳过常见依赖目录、链接、二进制及超大文件。

仍然只依赖 Python 标准库。文件搜索不解析 `.gitignore`，`grep` 不支持正则；压缩是手动触发，不是无损记忆，也不会清理磁盘历史。原有模型/工具执行权限边界未改变。

## 本地验证

Windows / Python 3.12 下 **58 项测试全部通过**，覆盖：

- 原有编码闭环、文件操作、会话恢复、命令退出码/超时/取消。
- SSE 文本片段、中文、交错工具调用参数、两种用量格式、缺少结束帧及异常响应。
- 本机 HTTP 服务等待客户端收到首段回调后才发送末段，证明流式回调发生在响应结束之前。
- 摘要失败和取消、工具调用配对、重复压缩、原始记录保留、压缩后恢复。
- 搜索排除目录、隐藏文件、二进制/大文件、扫描上限、Unicode 大小写折叠及长行片段。
- CLI 多行输入、状态显示、命令行压缩后继续对话。

`deepblue_agent-0.2.0` 的 wheel 构建及独立目录安装成功，安装后的 `deepblue --version` / `--help` 验证通过。

## 真实 DeepSeek 验证

使用请求模型 `deepseek-v4-flash`、30 秒网络操作超时，显式执行：

```bash
python scripts/live_smoke.py --v2
```

| 阶段 | 结果 | 耗时 |
| --- | --- | --- |
| 流式连接 | 返回“深蓝已连接” | 1.67 秒 |
| 搜索与编码修复 | 六个工具全部调用，3 个失败测试修复后全通过 | 12.69 秒 |
| 准备压缩 | 新进程恢复会话并添加后续对话 | 1.44 秒 |
| 摘要与继续对话 | 摘要保存后仍能正确回答早先的随机标记 | 5.39 秒 |

工具调用顺序：

```text
find → grep → read → read → shell（测试失败）
     → edit → shell（测试通过）→ write
```

联调脚本独立复跑原来的 3 个测试，退出码 0；测试文件 SHA-256 未改变。压缩前活动上下文为 **11,602 字节**，压缩后为 **3,865 字节**，约减少 66.7%。摘要包含最初的随机标记，最近保留轮次没有重复该标记，后续回复仍然正确。

本次共 11 次有用量记录的 API 请求（包括摘要请求），累计 `total_tokens` 29,280；该数值包含重复上下文，不等于费用。密钥未保存到源码或报告。
