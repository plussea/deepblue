## 轨迹发现

1. URL baseline 在修改属性时引入 `COMPLETIONS_PATH`，但任务结束时没有定义该常量，独立检查报 `NameError`。此前多轮查看调用方与搜索占用了步骤预算。不能把这个中间改动当成完成。
2. glob verified 连续运行多次 fnmatch 探索，随后只添加了 `import re`，尚未完成匹配函数修复就达到 8 步上限。Agent 没有正常结束，因此自动验收未获得介入机会；这次失败不能用于判断自动验收本身有效或无效。
3. 模型曾使用 `python check.py; echo ...` 的组合命令。前面的断言失败，最后的 echo 成功，使整条 Shell 命令退出码为 0。日志仍显示断言失败，独立检查也没有误判通过。后续可在工具使用指引中强调独立执行检查、保留失败退出码，而不是改变通用 Shell 的语义。
4. 全批共享 Token 预算使前面的探索消耗了后续任务的额度。交替两种模式顺序没有消除这种截断偏差。

## 下一步

- 在开发集上明确每任务步骤预算，提示先做最小修复与直接检查；记录只读探索次数，避免尚未修改就耗尽轮次。修改后作为新实验，不能覆盖本轮结果。
- 把批次预算分配到任务对，为后续任务预留额度；同时报告“已启动、已完成、预算中断、未运行”，不把未运行折算为模型失败。
- 在相同新预算下补齐双方任务并进行重复运行，再讨论 verified 的收益与开销。冻结保留集，不能根据其模型响应调整任务或提示。
- 在这组小样本之外增加真正的历史问题和外部项目，再评估泛化能力。
