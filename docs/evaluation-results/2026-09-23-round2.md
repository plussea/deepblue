# 第二轮真实 DeepSeek 对照结果

整理日期：2026-09-23；跟踪 [Issue #17](https://github.com/plussea/deepblue/issues/17)。本地实现与实验已完成，新增代码尚未提交、推送。

## 本轮变化

Agent 每轮收到剩余步数、最小局部修复与直接检查提示，最后两轮提醒收敛；提示不写入原始会话。评测预算按任务对分配，再等分到 baseline / verified，每次最多 8 步、8 次请求、40,000 Token 保守准入门槛与 120 秒。各次额度独立，不借用后续任务预算。总门槛为 80 次请求、400,000 Token、1200 秒。

沿用首轮相同的 5 个源码回归任务及检查哈希；每任务每模式运行一次，交替顺序。模型为 deepseek-v4-flash，最大输出 2048，关闭 thinking 和自动压缩。源码、任务、执行器及运行时哈希见 [脱敏 JSON](2026-09-23-round2.json)。原始报告保留，未重跑失败项；报告统计展示调整不改变实验结果。

首轮共享预算仅启动 4/10 次、1 次通过，详见 [首轮结果](2026-09-22.md)。本轮已消除后续任务因前面耗尽共享额度而未启动的问题；但预算与提示同时变化，不能把结果提升单独归因于步骤提示。每任务只有一次运行，且全部是同一项目源码上的人为回归缺陷，不能据 3/5 与 4/5 宣称 verified 普遍优于 baseline。

## 剩余问题与下一步

1. 改进准入估计：目前用 UTF-8 请求字节数、最大输出与余量保守预留，因此实际累计约 20,000 Token 时也可能触及 40,000 门槛。这不表示已经消费 40,000 Token；需要记录估计与实际差异，在保持预算保护的前提下减少过早停止。
2. 为直接验证与结束汇报预留预算：3 次修复已经通过，却未正常结束。下一轮应同时考察独立修复通过率和正常完成率。
3. 处理长输出截断：明确保留 incomplete 状态，评估减少冗长输出或受预算约束的续接，不能把截断当作成功。
4. 后续验证使用新的未见任务并预先固定预算；当前保留集已经运行，不应继续用于调参后声称未见。重复付费实验需单独规划，本轮不自动重跑。
